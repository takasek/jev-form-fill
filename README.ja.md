# Jev Form Fill

[English](README.md) · 日本語

クリップボードの文章から、現在のページのフォームに入力候補を作るChrome拡張です。項目名・見出し・選択肢を元の文章に対応付け、候補を確認してからDOM順に入力します。文章に書かれていない値は見送ります。明示された空欄やオフにも対応し、直前の入力を戻せます。フォームは自動送信しません。

**試用版 v0.1.5。文章から候補を作る場合は TypeSafe の API キーを使います。1Password 連携はキーなしで利用できます。TypeSafe の利用時は文章とフォーム情報をTypeSafeへ送信し、API利用料が発生する場合があります。** [データの扱い](PRIVACY.ja.md)を確認してください。

## 利用イメージ

![Chromeで候補を確認する](docs/images/review-proposals.jpg)

クリップボードから元の文章を読み、候補を確認して必要な欄だけに入力します。下の画像は、実際のChrome拡張と架空の登録フォームでの入力結果です。

![入力後のフォーム](docs/images/filled-form.jpg)

表示言語はブラウザに合わせて英語・日本語を選びます。拡張上部のLanguage／表示言語でも切り替えられます。フォームの項目名や入力値は翻訳しません。

## Mac で 1Password のプロフィールから一括入力する

標準の「身元情報」から姓・名・会社名・メール・電話・住所を取得できます。ただし、日本の会員登録でよく使うカナ、独立した郵便番号・都道府県・市区町村は、CLI 2.41.1 の標準テンプレートにありません。登録していない値の欄は手入力が必要です。住所は CLI が返す文字列を使い、番地などの境界を確定できる部分だけ分けます。漢字からの読みの生成や、住所の並び順の変更、都道府県・市区町村の推測は行いません。

よく使う日本のフォームをまとめて埋めるには、同じ身元情報に次の名前のカスタム項目をテキスト型で追加します。値は架空の例です。必要な項目だけを追加してください。[1Password での項目追加手順](https://support.1password.com/custom-fields/)

| 項目名 | 値の例 | 入力先 |
|---|---|---|
| セイ | カクウ | 姓の読み。ひらがな・カタカナ指定に合わせて変換 |
| メイ | ハナ | 名の読み |
| 郵便番号 | 150-0002 | 7桁の欄、3桁＋4桁の欄 |
| 都道府県 | 東京都 | テキスト欄、同じ表示名の選択肢 |
| 市区町村 | 架空市 | 市区町村の欄 |
| 番地 | 若葉町2-3-4 | フォームの「番地」に入れたい住所部分 |
| 建物名 | 架空棟101 | 建物名・部屋番号の欄 |

姓名をまとめて持つ場合は `氏名（姓 名）`、まとめた読みは `フリガナ`、住所1・住所2として分ける場合は `住所1`・`住所2` も使えます。独立した郵便番号がない場合は、住所中の `〒150-0002` のように明示された郵便番号だけを候補にします。

Mac の 1Password アプリと CLI（`op`）を用意し、「設定 → 開発者」で CLI との統合を有効にします。拡張 ID は `chrome://extensions` で確認します。拡張フォルダで Python 3.9 以降を使って次を実行し、一覧から使う身元情報の番号を選びます。複数なら `1,2` のように指定できます。アイテム ID のコピーは不要です。

```sh
python3 native/install.py EXTENSION_ID --choose
```

`--choose '保管庫名'` ならその保管庫の一覧に絞れます。ID を指定する従来の `--profile '保管庫名' IDENTITY_ITEM_ID` も使え、複数回指定できます。登録時は一覧の情報だけで存在を確認し、連絡先の値は取得しません。[CLI の項目一覧](https://www.1password.dev/cli/reference/management-commands/item#item-list)

フォーム上で「1Password から入力」を押します。複数登録している場合は身元情報を選ぶと、その1件だけの氏名・住所・連絡先が表示されます。「別の身元情報を選ぶ」で再選択でき、設定コマンドの再実行は不要です。再選択すると確認画面の手修正は消えます。入力先の見出しとプレビューを確認し、違う欄だけプルダウンで選び直して「まとめて入力」を押します。各欄で「入力しない」も選べます。単一フォームの配送先と連絡先など、人物の混在を示す情報がない既知の区画はまとめて提案します。区別がつかない区画や人物別の欄では、使う入力先を選びます。入力済みの欄を上書きするには、その欄で「入力済みの値を変更する」を選んでください。テキスト欄と単一選択欄に対応します。1Password からの入力は Undo 対象外です。

自宅と携帯など電話番号が複数あるときは「この入力先に使う電話番号」で番号を一度選びます。市外局番・市内局番・加入者番号にも同じ番号から分けた値が入ります。用途が指定されていない欄では、用途なしの番号が1つだけあればそれを初期案にします。各プルダウンには、項目の用途と値が表示されます。

姓・名をまとめるときは欄に明示された順序・空白に合わせます。電話は元の区切り、または番号の長さと一致する固定桁数を使います。住所は明示された「番地まで」「番地より前」「番地以降」「丁目まで」などに合わせて分けます。境界を確定できない場合や書式が異なる場合は、確認画面で入力値を直接修正できます。

英語の Address 欄（address-line1）では、`住所1` の値や、改行された住所と `Unit 4` などの部屋情報を利用できます。平文の住所を安全に分けられない場合も「住所全体（要確認）」を選び、必要な部分に修正できます。市区町村や国名の順序は推測しません。

確認中に元ページを操作すると、確認画面に戻った際に案内が出ます。「入力先を確認し直す」を押すと、1Password を再取得せずフォームを読み直します。同じ入力欄の手修正は引き継ぎます。人物や区画の選択と既入力の上書き許可はもう一度確認してください。入力中は件数を表示し、最後に約2秒待ってサイト側の変更を確認します。「現在の値を再確認」は、サイト側の補完が終わった後の値を再チェックします。

TypeSafe の AI 入力も使う場合は、AI の候補を先に確認・入力し、その後に 1Password から入力してください。1Password 入力後は、ページが個人情報を項目名や見出しに転記する可能性があるため、その文書での AI 解析を停止します。この時点で先行する AI 入力の Undo 履歴も消去します。続きの修正はフォーム上で行ってください。ページを再読み込みすると AI 解析を再開できますが、サイトによっては入力済みの値も失われます。

登録する身元情報の追加・削除には設定コマンドを再実行し、残したいものをすべて選びます。従来の `--field` 設定は個別入力として利用できます。別の Chrome データディレクトリには `--chrome-data` を指定してください。

ヘルパーにはセットアップ用の仮想環境を使わず、Python 3.9 以降の `/usr/bin/python3`、`/opt/homebrew/bin/python3`、`/usr/local/bin/python3` の順で動作確認したパスを使います。安定した別のパスは `--python /絶対パス/python3` で指定できます。Python の削除・移行や拡張の接続先変更後は、現在の拡張 ID で `python3 native/install.py EXTENSION_ID --repair` を実行すると、身元情報を選び直さずヘルパーを更新できます。

認証の頻度は 1Password のセッション、ロック、アカウントに依存します。CLI が新しいプロセスだから毎回 Touch ID が必要、とは断定できません。確認中の入力先の再確認は取得済みの値を使い、追加の CLI 読取を行いません。認証の省略や資格情報の保存で回避することはありません。[1Password の認証モデル](https://www.1password.dev/cli/app-integration-security)

削除する場合は Chrome のユーザーデータディレクトリの `NativeMessagingHosts` 内の `local.jev_form_fill.onepassword.json` と `local.jev_form_fill.onepassword` フォルダを削除します。

## インストール

Chrome 116以上が対象です。ビルドやNode.jsのインストールは不要です。GitHubから配布するソースをローカルで読み込む方式です。

1. リポジトリをダウンロードして展開します。配布用ZIPを使う場合は、ZIP内の `jev-form-fill` フォルダを展開します。
   Mac ではそのフォルダで `python3 native/stage.py` を実行すると、常用ファイルを `~/Library/Application Support/Jev Form Fill/extension` に配置します。展開元を移動・削除しても、この固定フォルダから読み込んだ拡張には影響しません。
2. Chromeで `chrome://extensions` を開き、右上の「デベロッパーモード」をオンにします。
3. 「パッケージ化されていない拡張機能を読み込む」を押し、`manifest.json` があるフォルダを選びます。Mac で上の配置コマンドを使った場合は、表示された固定フォルダを選びます。
4. ツールバーの拡張機能メニューから「Jev Form Fill」を開きます。必要なら固定します。

更新時は新しい展開元から `python3 native/stage.py` を再実行し、`chrome://extensions` で拡張を再読み込みしてください。配置先の固定フォルダ自体は移動しないでください。別の読み込み元へ移行すると Chrome の拡張 ID が変わるため、現在の ID を使って前述の `--repair` を実行します。1Password ヘルパーを更新する場合も `--repair` を使えます。

## 使い方

1. 設定値やメモをコピーし、入力先のページを開きます。
2. 拡張を開き、「クリップボードから読む」を押します。文章欄への手動貼り付けもできます。
3. 「APIキーの設定」にTypeSafe APIキーを入力します。
4. 「TypeSafeへ送って候補を作る」を押します。処理中はポップアップを開いたままにしてください。
5. 候補を確認し、変更したくない項目のチェックを外して「選んだ項目に入力」を押します。既存の値も、選んで適用すれば書き換わります。
6. 適用結果とページ側の値を確認し、フォームの送信はご自身で行います。「直前の入力を戻す」で最後の書き換えを取り消せます。

適用後の失敗は**拡張のポップアップ内**に件数と理由を表示します。フォーム上に目印は付けません。「ページが値を受け付けませんでした」「入力後にページが値を変更しました」は入力失敗です。ポップアップを閉じると表示は消えます。適用後の「0件の候補」は、未適用の候補が残っていないという意味です。

入力に応じて新しい欄が現れた場合は、もう一度候補を作ってください。分析後に手入力した値や、意味・選択肢が変わった項目は適用を見送ります。Undoでも後から手で編集した値は残します。ページ移動・再読み込み・拡張の再読み込みで候補とUndo情報は失われます。

## 対応範囲

| 対応 | トップレベル文書のinput（text・email・tel・url・search・number・date・time・datetime-local・checkbox・radio）、textarea、単一選択select |
| --- | --- |
| 対象外 | password、file、hidden、month・week・range・color、disabled・readonly、送信ボタン、複数選択select、iframe、shadow DOM、contenteditable、ネイティブ入力要素のない独自UI |
| 元文章の上限 | 12,000文字・120行、1回の分析は160項目まで |
| 値の扱い | 元文章の引用値または一行の範囲をそのまま切り出す。複数行の合成、言い換え、日付計算はしない |

- radioは同名・同一formのグループ全体を扱える場合だけ操作します。一部の選択肢がdisabledなどの場合は見送ります。
- ネイティブ `details` は読み取り時だけ開いて元に戻します。それ以外の折りたたみは、ご自身で開いてから分析してください。
- credential・paymentらしい名前のテキスト欄も除外しますが、判定はヒューリスティックです。元文章の秘密情報を自動除去しません。
- 値の範囲選択は一行240トークンまでです。多数の選択肢や長い文章はAPIの文脈上限に達する場合があります。
- TypeSafe の経路では設定後に読戻しを行い、全項目への適用後に650ms待って再確認します。それ以降の変更は継続監視しません。
- Jevの判定には揺れがあります。同じ文章・フォームでも毎回同じ候補になる保証はありません。候補と入力後の値を確認してください。

## データと費用

解析先はTypeSafeの `https://api.typesafe.ai/v1/systemone`、モデルは `jev-latest` です。元の文章と対象項目の名前・見出し・型・選択肢を送ります。既存の入力値、Cookie、ページURL、ページ本文全体は解析要求に含めません。項目名・見出しに含まれる個人情報は送られます。アクセス解析はありません。

8項目ずつ分析し、1バッチあたり1〜4回のAPI要求を行います。HTTPエラーの自動再試行はしません。APIキーは通常、開いているポップアップ内だけに保持します。保存を明示した場合だけ `chrome.storage.local` に保存します。詳細は [PRIVACY.ja.md](PRIVACY.ja.md) を参照してください。

権限は `activeTab`、`scripting`、`storage`、`clipboardRead`、TypeSafe API ホスト、1Password 連携用の `nativeMessaging` です。

## 試験と開発

開発・試験・ZIP作成は、[ソースリポジトリ](https://github.com/takasek/jev-form-fill)をダウンロードまたはcloneし、そのルートで実行してください。配布用ZIPには開発・試験用のファイルを含めません。Node.js 22以上で実行できます。テストはモデル回答とChrome APIを模擬し、実APIやAPIキーは使いません。

```sh
npm ci --ignore-scripts
npm test
```

架空のイベント登録フォームで、同名欄、空欄・オフ、先頭ゼロ、動的欄、偽指示、サイトによる値の書き戻しなどを試せます。

```sh
node lab/server.js --port 0
```

表示されたURLをChromeで開きます。サーバーは127.0.0.1だけで待ち受け、送信結果をGit管理対象外の `.local/form-fill-lab/receipts/` に保存します。詳しくは [試験フォームの使い方](https://github.com/takasek/jev-form-fill/blob/main/lab/README.md) と [検証結果・限界](https://github.com/takasek/jev-form-fill/blob/main/docs/validation.md) を参照してください。

GitHub Appの設定例も [examples/](https://github.com/takasek/jev-form-fill/tree/main/examples) にあります。実際のGitHub App作成画面での入力互換性は未検証です。

配布用ZIPはPython 3.9以上で作成できます。

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
npm run package
```

ZIPには拡張の実行ファイル、英語・日本語のREADMEとプライバシー説明、スクリーンショット、ライセンスを入れます。試験サーバー、受信データ、依存ライブラリ、APIキーは含めません。既存のZIPは上書きしないため、再作成時は先に対象ファイルを移動してください。

## 仕組みと資料

根拠の行と完全な引用値を候補として選び、全文に照らすNoul確認を経て入力可能にします。引用されていない値は始点・終点から元文字列を切り出します。空欄・オフは、情報欠落とは別の明示指示として確認します。しきい値はアプリの暫定方針で、正確さの実測値ではありません。
